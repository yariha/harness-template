# Maintenance Routines

empirical-coding의 보조 문서다. 반복되는 유지보수를 한 문장 프롬프트 루틴으로 돌린다.
등록: Claude Code `/loop`(로컬, 주기 실행) 또는 `/schedule`(클라우드 routine, 노트북을 닫아도 동작).

## 예시 루틴

| 루틴 | 프롬프트 | 주기 |
| --- | --- | --- |
| 죽은 코드 정리 | "정적·동적 분석으로 사용되지 않는 코드를 찾아 제거하는 PR을 올려라." | 매일 |
| 실험 플래그 졸업 | "100% 롤아웃된 플래그를 찾아 분기를 제거하고 기본 동작으로 확정하는 PR을 올려라." | 매주 |
| 테스트 보강 | "커버리지가 낮고 위험한 영역에 의미 있는 테스트를 추가하는 PR을 올려라." | 매주 |
| 무의미한 테스트 제거 | "아무것도 검증하지 않거나 중복된 테스트를 찾아 제거하는 PR을 올려라." | 매주 |
| Abstraction police | "거의 같은 추상화가 여러 곳에 재구현된 것을 찾아 하나로 통합하는 PR을 올려라." | 매주 |
| 문서 지도 보수 | "maintain-highway 스킬을 실행합니다." (narrow 모드) | 매일 |

## 원칙

- 결과는 항상 PR로 올리고 사람이 리뷰한다. 루틴이 main에 직접 쓰지 않는다.
- 루틴끼리 컨텍스트는 공유하지 않는다. 상태 공유가 필요하면 `RESEARCH.md` 같은 장부 파일로만 한다.
- 처음에는 1~2개만 켜고 PR 품질을 보며 늘린다.
- 루틴 결과가 같은 방식으로 반복해서 틀리면 그때 프롬프트에 한 줄 추가한다 (Ablation 원칙).
- SSOT Core Principles의 허락 필수 변경(예: migration)은 루틴이 절대 만들지 않는다.
